## 멀티 네임스페이스 환경에서의 Ingress 활용 및 격리 전략

쿠버네티스 운영 아키텍처에서 인그레스(Ingress)를 활용하여 여러 네임스페이스(`megaprod`, `megadev`)에 서비스를 노출하는 방법은 크게 두 가지로 나뉩니다. 하나의 컨트롤러로 통합 관리하는 **공유형 아키텍처**와 각 네임스페이스에 전용 컨트롤러를 두는 **격리형 아키텍처**입니다.

---

### [Case 1] 공유형 인그레스 아키텍처 (통합 관리)

이미 설치된 하나의 인그레스 컨트롤러를 사용하여 여러 네임스페이스의 트래픽을 분기하는 효율적인 방식입니다.

#### 1. 인그레스 설정 파일 작성

* **파일명**: `shared-ingress.yaml`

```yaml
# 운영 환경용 (megaprod)
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: prod-ingress
  namespace: megaprod
spec:
  ingressClassName: nginx       # 인그레스 클래스 네임 실제로는 많이 나뉨 예시: 쿠팡 - 여성복/식료퓸/생필품/등등
  rules:
  - host: prod.mega-it.com
    http:                       # http를 읽겠다 = 브라우저에 써있는 url을 보겠다
      paths: 
      - path: /                 # 루트
        pathType: Prefix
        backend:
          service:
            name: prod-service
            port:
              number: 80
---
# 개발 환경용 (megadev)
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: dev-ingress
  namespace: megadev
spec:
  ingressClassName: nginx
  rules:
  - host: dev.mega-it.com
    http:
      paths:
      - path: /                   # 둘 다 루트라는 건 웹서버가 각각 다르다는 것 
        pathType: Prefix
        backend:
          service:
            name: dev-service
            port:
              number: 80

```

#### 2. 실행 및 확인 방법

```bash
# 인그레스 규칙 적용
kubectl apply -f shared-ingress.yaml

# 적용 결과 확인
kubectl get ingress -A

```

---

### [Case 2] 격리형 인그레스 아키텍처 (네임스페이스 전용)

보안이나 성능 격리가 극도로 중요한 경우, 각 네임스페이스마다 독립적인 컨트롤러 엔진을 설치하는 방식입니다.

#### 1. 네임스페이스별 설정 파일 작성 (Helm Values)

* **파일명**: `values-prod.yaml` (운영용)

```yaml
controller:
  ingressClassResource:
    name: prod-nginx
  scope:
    enabled: true
    namespace: "megaprod"
  replicaCount: 2

```

* **파일명**: `values-dev.yaml` (개발용)

```yaml
controller:
  ingressClassResource:
    name: dev-nginx
  scope:
    enabled: true
    namespace: "megadev"
  replicaCount: 1
  admissionWebhooks:
    enabled: false

```

#### 2. 실행 및 설치 방법 (Helm)

```bash
# 운영 환경 전용 컨트롤러 설치
helm install prod-ingress ingress-nginx/ingress-nginx -f values-prod.yaml --namespace megaprod

# 개발 환경 전용 컨트롤러 설치
helm install dev-ingress ingress-nginx/ingress-nginx -f values-dev.yaml --namespace megadev

```

---

### 3. 구성 결과 검증

```bash
# 설치된 인그레스 클래스 목록 확인
kubectl get ingressclass

# 네임스페이스별 컨트롤러 실행 상태 확인
kubectl get pods -n megaprod
kubectl get pods -n megadev

```

---

### 💡 실전 전문 팁 (Expert Tips)

* **비용 최적화**: AWS 환경에서 Case 2 방식은 로드밸런서가 네임스페이스 개수만큼 생성되어 **추가 과금(LB 생성 비용)**이 발생합니다. 학습용으로는 Case 1(공유형)을 권장합니다.
* **유료 서비스 주의**: `LoadBalancer` 타입 서비스는 외부 IP 할당을 위해 생성 즉시 비용이 발생하므로 실습 후 반드시 `helm uninstall`로 리소스를 삭제하십시오.
* **호스트 파일 설정**: 실제 도메인이 없는 실습 환경에서는 로컬 PC의 `/etc/hosts` 파일에 로드밸런서 IP와 `prod.mega-it.com` 등의 호스트명을 매핑하여 테스트하십시오.
