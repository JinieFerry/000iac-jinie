## 네임스페이스(Namespace) 생성 및 관리

쿠버네티스에서 **네임스페이스**는 단일 클러스터 내의 리소스들을 논리적으로 격리하는 가상 클러스터 역할을 합니다. 요청하신 운영 환경(`megaprod`)과 개발 환경(`megadev`)을 분리하여 관리하는 것은 자원 간섭을 방지하고 보안 정책(RBAC)을 적용하는 아키텍처의 기본입니다.

만드는 방법은 1의 CLI로 만들기와 2의 YAML로 만드는 방법이 있고, 원성두 팀장님은 2의 YAML로 생성하는 방식을 권장함. 
### 1. CLI를 이용한 즉시 생성

가장 빠르고 직관적인 방법은 `kubectl` 명령어를 직접 사용하는 것입니다.

```bash
# 운영 환경 네임스페이스 생성
kubectl create namespace megaprod

# 개발 환경 네임스페이스 생성
kubectl create namespace megadev

```

### 2. YAML 정의서를 이용한 생성 (IaC 방식) <- 이걸로 하길 바람

실무에서는 인프라를 코드로 관리(Infrastructure as Code)하기 위해 YAML 파일을 작성하여 형상 관리 도구(Git)에 보관하는 방식을 권장합니다.

* **namespaces.yaml**

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: megaprod   #서비스용
  labels:          # 라벨은 여러개 붙일 수 있음 디테일하게 구분할 수 있게
    env: production
---
apiVersion: v1
kind: Namespace
metadata:
  name: megadev   #개발용
  labels:
    env: development

```

* **적용 명령어**

```bash
kubectl apply -f namespaces.yaml  #파일네임이 .yml이라면 .yml으로 적용

```

---

### 3. 생성 결과 확인

생성된 네임스페이스가 정상적으로 리스트에 존재하는지 확인합니다.

```bash
kubectl get namespaces --show-labels

```

---

### 💡 실전 전문 팁 (Expert Tips)

* **컨텍스트 전환(kubectx)**: 여러 네임스페이스를 오가며 작업할 때 `kubectl config set-context --current --namespace=megaprod` 명령어를 매번 치는 것은 비효율적입니다. 오픈소스 도구인 **kubectx**나 **kubens**를 활용하여 작업 환경을 빠르게 전환하십시오.
* **자원 격리(Resource Quota)**: `megadev` 환경의 리소스가 비대해져 `megaprod` 운영 환경에 영향을 주는 것을 방지하려면, 각 네임스페이스별로 **ResourceQuota**를 설정하여 CPU와 메모리 사용량의 상한선을 반드시 지정해야 합니다.
* **과금 관리**: AWS EKS 환경에서 네임스페이스별로 리소스를 분리하더라도, 클러스터 자체 비용(Control Plane)은 동일합니다. 하지만 Fargate를 사용할 경우 네임스페이스별 Pod 실행 시간에 따라 비용이 합산되므로 모니터링이 필요합니다.
