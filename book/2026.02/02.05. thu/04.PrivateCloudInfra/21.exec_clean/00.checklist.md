아래 항목 중 하나라도 정상 상태가 아니면 실습이 꼬인다.  
모두 체크 한 후 다음 단계를 진행한다. (00.checklist 확인 => 10.k8s-basics/10.nginx-nodeport.yaml)

1. 노드 상태 확인 : `kubectl get nodes`
   + 모든 노드 Ready
   +  실습에서 사용하는 노드 중 하나라도 NotReady가 있으면 Ready를 먼저 시키고 실습 진행
     + control-plane: vmmaster1
     + worker: vm1
    NotReady 상태에서는 Pod 스케줄링 / Service 접근 / NodePort 테스트가 모두 불안정해진다.

>```
>master@vmmaster1:~$ kubectl get nodes -o wide
>NAME        STATUS   ROLES           AGE     VERSION    INTERNAL-IP       EXTERNAL-IP   OS-IMAGE             KERNEL-VERSION      CONTAINER-RUNTIME
>vm1         Ready    <none>          5d21h   v1.30.14   192.168.115.1     <none>        Ubuntu 24.04.3 LTS   6.14.0-37-generic   containerd://1.7.28
>vmmaster1   Ready    control-plane   5d22h   v1.30.14   192.168.115.251   <none>        Ubuntu 24.04.3 LTS   6.14.0-37-generic   containerd://1.7.28
>```

2. API 서버 정상 동작 확인 : `kubectl cluster-info`
   + 정상 응답 : https://<MASTER-IP>:6443 <- 열어둔 포트가 떠야 함
   + 정상 출력 예시:
   + `Kubernetes control plane is running at https://<MASTER-IP>:6443`

>```
>master@vmmaster1:~$ kubectl cluster-info
>Kubernetes control plane is running at https://192.168.115.251:6443
>CoreDNS is running at https://192.168.115.251:6443/api/v1/namespaces/kube-system/services/kube-dns:dns/proxy

>To further debug and diagnose cluster problems, use 'kubectl cluster-info dump'.
>```

   + 또는 직접 확인: `curl -k https://<MASTER-IP>:6443/healthz`
     > 정상 응답: ok
   + 응답없음/타임아웃 시 6443포트 자체 혹은 방화벽 문제를 의심하고 아래를 확인한다.
     > 6443/tcp 포트 미개방
     > 방화벽(UFW / firewalld) 차단
     > control-plane 서비스 비정상
     
    
3. swap off 확인 : `sudo swapon --show`
   + sawp on을 출력하는 명령으로 출력이 없어야 정상 상태
   + swap on 상태에서는 kubelet 정상 동작 불가하므로 OS 사전 정비 단계에서 필수 완료 요소이다.
     
4. 방화벽/포트 확인:
   + 필수포트 열려있어야 함:
     + API Server: 6443/tcp
     + NodePort: 30080/tcp (실습용) 
   
   + VM / 클라우드 환경에서는 다음을 반드시 확인:
     >UFW / firewalld
     
    + 클라우드 환경일 경우:
       >Security Group

       + 인바운드 규칙

       + VM 환경일 경우:

       + 브리지 / NAT 네트워크 정책

       + 호스트 방화벽

       + NodePort는 Pod가 아니라 Node가 받는다는 점을 항상 의식한다.
     
6. 이미지 PULL 테스트(네트워크 확인)
```
kubectl run test --image=nginx --restart=Never
kubectl delete pod test -w
# Running 뜨면 테스트 정리로 넘어가기
# 테스트 정리: kubectl delete pod test
```
   + 정상 상태: 상태: Running → Completed 또는 Running
>```
>#테스트
>master@vmmaster1:~$ kubectl run test --image=nginx --restart=Never
>pod/test created
>```

>```
>#결과 길게 
>master@vmmaster1:~$ kubectl get pod test -w
>NAME   READY   STATUS              RESTARTS   AGE
>test   0/1     ContainerCreating   0          2m24s
>```


7. 이미지 PULL 테스트 후 반드시 정리 `kubectl delete pod test`
   + 예견되는 문제 사항
      +ImagePullBackOff
      +ErrImagePull
   + 점검 항목
      + 노드의 인터넷 연결 여부
      + DNS설정
      + 프록시 설정 (http_proxy / https_proxy)
      + 사설망 환경에서 외부 레지스트리 접근 가능 여부
    
>```
>#정리하기
>master@vmmaster1:~$ kubectl delete pod test
>pod "test" deleted
>```
