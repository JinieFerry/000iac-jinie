GitHub 저장소의 파일 구조를 분석하여 정적인 `contents.html` 파일을 자동으로 생성하고 업데이트하는 파이썬 스크립트입니다. 이 방식은 매번 API를 호출하지 않고, 로컬 환경이나 **GitHub Actions(깃허브 액션)** 환경에서 실행하여 결과물을 저장소에 반영할 때 유용합니다.

---


### 작업 목표 : 
          1) 트리거 : 내 저장소에 새로운 파일이나 업데이트가 되는 파일이 발생하면
          2) 작업(workflows) : 디렉토리와 파일들을 검색하여 xxx.html 파일들을 수집하고
                              파일명 순으로 목차를 보여주는 contents.html 파일을 생성/업데이트 하라. 

### 작업 단계 : 
    1 단계 : '작업'에 해당하는 프로그램을 만든다.  update_contents.py 
    2 단계 : 이 파이썬 프로그램을 실행한다.  
            1) 저장소 홈디렉토리 -> code -> codespaces -> code space on main 버튼 클릭(임시 프로그래밍 공간임) -> VS code 화면이 나옴
            2) 하단 터미널에서   $ python update_contents.py   # 실행하면 왼쪽 리스트에 contents.html이 생성됨
            3) 이 vs code 작업공간은 임시 공간이므로 생성된 contents.html을 내 저장소로 커밋 푸쉬해 주기
               $ git add contents.html
               $ git commit -m "update"
               $ git push            # 내 저장소에 contents.html이 생성되거나 업데이트 됨. 

    3 단계 : Action 작업 등록하기
             1) .github/workflows/update.yml 파일 만들기(GPT로 생성) - update_contents.py를 실행하라.
             2) Action 등록   - 상단 Actions -> All workflows 밑에 새로 만든 update.yml의 work name 을 선택 
             
             


## 파이썬 기반 contents.html 자동 생성 프로그램

이 프로그램은 지정된 디렉토리 내의 폴더와 `.html` 파일을 탐색하여 트리 구조의 HTML 문서를 생성합니다.

### 1. 파이썬 스크립트 (update_contents.py)

```python
import os

def generate_contents_html(target_dir="."):
    """
    지정된 디렉토리의 폴더와 html 파일 리스트를 추출하여 contents.html을 생성합니다.
    """
    # 1. 파일 및 디렉토리 리스트 수집
    items = os.listdir(target_dir)
    
    # 제외할 항목 (숨김 파일, 자기 자신 등)
    exclude_list = ['.git', '.github', 'contents.html', 'update_contents.py']
    
    filtered_items = [
        item for item in items 
        if item not in exclude_list and (os.path.isdir(item) or item.endswith('.html'))
    ]
    
    # 이름 순으로 정렬 (폴더 우선)
    filtered_items.sort(key=lambda x: (not os.path.isdir(x), x.lower()))

    # 2. HTML 템플릿 작성
    html_start = """<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>강의 자료 목차</title>
    <style>
        body { font-family: sans-serif; padding: 40px; line-height: 1.8; }
        h1 { color: #2c3e50; border-bottom: 2px solid #3498db; display: inline-block; }
        ul { list-style: none; padding-left: 0; }
        li { margin-bottom: 8px; border-bottom: 1px dotted #ccc; }
        .dir { font-weight: bold; color: #e67e22; }
        .file { color: #34495e; }
        a { text-decoration: none; color: inherit; }
        a:hover { text-decoration: underline; color: #3498db; }
        .icon { margin-right: 10px; }
    </style>
</head>
<body>
    <h1>📂 저장소 콘텐츠 목록</h1>
    <ul>
"""

    html_end = """    </ul>
    <p style="margin-top:30px; font-size: 0.8em; color: #7f8c8d;">
        마지막 업데이트: {update_time}
    </p>
</body>
</html>
"""

    # 3. 리스트 항목 생성
    import datetime
    content_list = ""
    for item in filtered_items:
        is_dir = os.path.isdir(item)
        icon = "📁" if is_dir else "📄"
        class_name = "dir" if is_dir else "file"
        display_name = f"{item}/" if is_dir else item
        
        content_list += f'        <li><span class="icon">{icon}</span><a href="./{item}" class="{class_name}">{display_name}</a></li>\n'

    # 4. 파일 쓰기
    now = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    full_html = html_start + content_list + html_end.format(update_time=now)
    # 한글이 들어가 있으니 utf-8을 사용
    with open("contents.html", "w", encoding="utf-8") as f:
        f.write(full_html)
    
    print(f"성공: contents.html 파일이 업데이트되었습니다. ({now})")

if __name__ == "__main__":
    generate_contents_html()

```

### 2. 주요 로직 설명

* **OS Module (Operating System Module, 운영체제 모듈)**: 파이썬 표준 라이브러리로, 파일 시스템 경로를 조작하고 디렉토리 내 파일 목록을 가져오는 데 사용됩니다.
* **List Comprehension (리스트 컴프리헨션)**: `.git` 폴더나 현재 실행 중인 스크립트 파일 등 불필요한 항목을 효율적으로 필터링하기 위해 사용되었습니다.
* **Static Generation (정적 생성)**: 클라이언트 사이드에서 API를 호출하는 대신, 서버(혹은 로컬)에서 미리 HTML을 그려서 배포하는 방식입니다. 로딩 속도가 빠르고 API 호출 제한 문제를 해결할 수 있습니다.

### 3. 실전 활용 팁: GitHub Actions 자동화

매번 파일을 수정할 때마다 파이썬을 실행하기 번거롭다면, 저장소의 `.github/workflows/` 폴더에 아래 설정 파일(`update.yml`)을 만들어 넣으세요. 파일을 푸시할 때마다 자동으로 리스트가 갱신됩니다.

```yaml
name: Update Contents List
on: [push]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Set up Python
        uses: actions/setup-python@v2
        with:
          python-version: '3.x' # 버전이 많이 바뀌면 실행이 안되기 때문에 파이썬 3점대 사용으로 고정
      - name: Run Script
        run: python update_contents.py
      - name: Commit and Push
        run: |
          git config --global user.name 'github-actions'
          git config --global user.email 'action@github.com'
          git add contents.html
          git commit -m "Auto-update contents.html" || exit 0
          git push

```

---
GitHub Actions(깃허브 액션)를 사용하여 앞서 만든 파이썬 프로그램을 자동화하는 구체적인 방법과 메뉴 위치를 단계별로 안내해 드립니다.

## GitHub Actions 자동화 설정 단계

이 작업을 완료하면 저장소(Repository)에 파일이 추가되거나 변경될 때마다 파이썬 스크립트가 실행되어 `contents.html`을 최신 상태로 갱신합니다.

### 1. 메뉴 위치 및 워크플로 파일 생성

1. 해당 **GitHub 저장소(Repository)** 메인 페이지로 접속합니다.
2. 파일 목록 상단의 **[Add file]** 버튼을 누르고 **[Create new file]**을 클릭합니다.
3. 파일명 입력란에 다음과 같이 경로를 포함하여 입력합니다:
* `.github/workflows/update-list.yml`
* (주의: `.github` 앞에 점이 있으며, `workflows`는 복수형입니다.)



### 2. 설정 값 작성 (YAML 스크립트)

새로 만든 파일의 본문에 아래 내용을 복사해서 붙여넣습니다.   
사람이 직접 로그파일을 자르면 감사 대상이 될 수 있기 때문에 사람이 하지 않도록 한다. (로그파일은 너무 크기 때문에 잘라서 써야하지만 특정 부분을 사람이 건들면 안되기 때문에)     
데이터 유출과 다운로드 모두 로그에 기록된다. (로그는 시스템엔지니어가 접근 가능하고, cctv와 같은 역할을 하기 때문에)

```yaml
name: Auto Update Contents  # 워크플로 이름

on:
  push:
    branches: [ main ]  # main 브랜치에 푸시가 일어날 때마다 실행
  workflow_dispatch:      # 필요한 경우 수동으로도 실행 가능하도록 설정

jobs:
  build:
    runs-on: ubuntu-latest  # 가상 환경 리눅스 서버에서 실행 # 깃허브의 가상환경을 잠시 빌려 쓰는 것
    
    steps:
      - name: Checkout Code
        uses: actions/checkout@v3  # 저장소의 코드를 가상 서버로 가져옴

      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.10'

      - name: Run Update Script
        run: python update_contents.py  # 이전에 만든 파이썬 파일 실행

      - name: Commit and Push changes
        run: |
          git config --global user.name "github-actions[bot]"
          git config --global user.email "github-actions[bot]@users.noreply.github.com"
          git add contents.html # 가상저장소에서 수정했으니 내 실제 저장소에도 add해야 함
          git commit -m "chore: contents.html 자동 업데이트" || echo "변경 사항 없음"
          git push # 가상 저장소에서 수정했으니 내 실제 저장소에도 push 해야 함

```

### 3. 권한 설정 (중요: 작업 실패 방지)

GitHub Actions가 파일을 수정해서 다시 저장소에 올릴 수 있도록 쓰기 권한을 주어야 합니다.

1. 저장소 상단 메뉴의 **[Settings]** 탭을 클릭합니다.
2. 왼쪽 사이드바 메뉴에서 **[Actions]** > **[General]**을 선택합니다.
3. 페이지 맨 아래쪽 **[Workflow permissions]** 항목에서 **'Read and write permissions'**를 선택합니다.
4. **[Save]** 버튼을 눌러 저장합니다.

### 4. 실행 확인 (Monitoring)

1. 상단 메뉴의 **[Actions]** 탭을 클릭합니다.
2. 왼쪽 목록에서 'Auto Update Contents'라는 이름의 워크플로가 실행 중인지 확인합니다.
3. 초록색 체크 표시가 나타나면 성공적으로 `contents.html`이 업데이트된 것입니다.

### 💡 주요 용어 및 유의 사항

* **Workflow (워크플로)**: 자동화된 전체 절차를 의미하며, `.yml` 파일에 정의됩니다.
* **YAML (YAML Ain't Markup Language, 야믈)**: 설정 파일을 작성할 때 사용하는 사람이 읽기 쉬운 데이터 직렬화 양식입니다.
* **Git Config**: 가상 서버에서 수정된 파일을 다시 내 저장소로 푸시하기 위해 필요한 사용자 인증 설정입니다.
* **Github Token (GitHub 토큰)**: 별도의 설정 없이도 `actions/checkout`을 통해 자동으로 부여되는 `GITHUB_TOKEN`을 사용하여 보안상 안전하게 파일을 푸시합니다.
