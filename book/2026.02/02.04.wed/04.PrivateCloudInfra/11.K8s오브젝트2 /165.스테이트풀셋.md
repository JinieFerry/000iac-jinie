## 스테이트풀셋(StatefulSet)의 이해와 활용

**스테이트풀셋(StatefulSet)**은 데이터베이스나 분산 파일 시스템과 같이 **상태를 유지해야 하는(Stateful) 애플리케이션**을 관리하기 위한 컨트롤러입니다. 포드(Pod)의 순서와 고유성을 보장하며, 포드가 재시작되더라도 데이터와 네트워크 식별자가 유지되도록 설계되었습니다.

### 1. 스테이트풀셋의 핵심 특징: DB는 상태를 항상 기록해 둠(추적,보안:누가 뭐를 write,modify,delete했는지 순서가 중요함) <> 스테이트리스는 상태를 전혀 기록,저장하지 않음:프론트 웹서버 같은 정적 페이지

디플로이먼트가 "언제든 교체 가능한 복제본"을 만든다면, 스테이트풀셋은 **"이름과 데이터가 고정된 개별 객체"**를 만듭니다.

* **고유한 네트워크 식별자**: 포드 이름 뒤에 `0, 1, 2`와 같이 인덱스가 붙으며, 재시작되어도 이 이름이 유지됩니다. (예: `db-0`, `db-1`)
* **순차적인 생성 및 삭제**: 포드를 0번부터 순서대로 하나씩 생성하며, 삭제할 때는 역순(가장 높은 번호부터)으로 제거합니다. 이는 분산 시스템의 데이터 정합성을 위해 필수적입니다.
* **안정적인 스토리지(PVC)**: 포드마다 별도의 **PersistentVolume(PV)**이 할당됩니다. 포드가 삭제 후 재생성되어도 기존에 연결되었던 데이터를 그대로 다시 연결합니다.

---

### 2. 스테이트풀셋 vs 디플로이먼트 비교

| 구분 | 디플로이먼트 (Deployment) | 스테이트풀셋 (StatefulSet) |
| --- | --- | --- |
| **대상 앱** | 웹 서버, API 등 (Stateless) | DB, 메시지 큐, 분산 저장소 |
| **포드 명칭** | `web-abcd12` (랜덤 해시) | `db-0`, `db-1` (고정 인덱스) |
| **스토리지** | 모든 포드가 같은 볼륨 공유 가능 | 각 포드가 독립된 전용 볼륨 사용 |
| **업데이트** | 한꺼번에 또는 롤링 업데이트 | 순차적 업데이트 (RollingUpdate) |

### 3. 스테이트풀셋 YAML 예시 (MariaDB/MySQL 구조)

스테이트풀셋은 개별 포드에 접근하기 위해 보통 **헤드리스 서비스(Headless Service)**와 함께 사용됩니다.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mariadb-service
spec:
  clusterIP: None            # 헤드리스 서비스 설정 (IP 대신 DNS로 각 포드 식별)
  selector:
    app: mariadb
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mariadb
spec:
  serviceName: "mariadb-service" # 연결된 헤드리스 서비스 이름
  replicas: 3
  selector:
    matchLabels:
      app: mariadb
  template:
    metadata:
      labels:
        app: mariadb
    spec:
      containers:
      - name: mariadb
        image: mariadb:10.5
  volumeClaimTemplates:      # 4. 각 포드마다 개별 볼륨을 생성하는 설계도
  - metadata:
      name: data
    spec:
      accessModes: [ "ReadWriteOnce" ]
      resources:
        requests:
          storage: 10Gi      # 포드당 10GB 할당

```

---

### 4. 헤드리스 서비스(Headless Service)의 역할

스테이트풀셋은 개별 포드의 주소가 중요합니다. `clusterIP: None`으로 설정된 헤드리스 서비스는 로드 밸런싱을 하지 않고, DNS 조회를 통해 각 포드의 개별 IP(예: `mariadb-0.mariadb-service`)를 직접 반환합니다. 클러스터 내부에서 마스터 DB와 슬레이브 DB를 구분하여 접속할 때 필수적입니다.

### 💡 실무 전문가의 팁: 삭제 시 주의사항

강사님은 수강생들에게 **"스테이트풀셋을 삭제해도 볼륨(PVC)은 자동으로 삭제되지 않는다"**는 점을 반드시 강조하셔야 합니다. 이는 실수로 스테이트풀셋이 삭제되었을 때 중요한 데이터를 보호하기 위한 안전장치입니다. 데이터를 완전히 지우려면 PVC를 수동으로 하나씩 삭제해야 합니다.

---

### ⚠️ 비용 및 유료 전환 주의사항

* **스토리지 누적 과금**: `volumeClaimTemplates`를 사용하면 `replicas` 수만큼 독립적인 **AWS EBS 볼륨**이 생성됩니다. 예를 들어 3개의 복제본에 각각 100GB를 할당하면 총 300GB의 EBS 비용이 발생하며, **포드를 중지해도 볼륨 비용은 계속 청구**됩니다.
* **프로비저닝 지연**: 클라우드 환경에서 스테이트풀셋 스케일 아웃 시, 각 포드마다 새로운 EBS 볼륨을 생성하고 연결하는 과정에서 디플로이먼트보다 더 긴 시간이 소요될 수 있습니다.
