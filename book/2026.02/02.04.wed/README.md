### Service
+ 백엔드/프론트엔드 = service IP = Cluster IP (service 별로 묶은 것과 전체를 묶은 것 모두 클러스터라고 부름)

+ yaml에서의 서비스: 통신 서비스 = 접속 서비스(낮은 단계)

+ 클러스터 아이피는 내부 통신 = 우리는 이름으로 통신 (아이피는 계속 바뀌니까) : 개발자와 시스템 담당자가 합쳐서 만든게 k8s라서 개념이 공존

+ 아이피는 내부적으로 사용, 인터넷 쓸 때 도메인 쓰 듯이 우리는 이름으로 통신 = DNS 서버가 컨트롤 플레인에 들어감

### Node 
+ Node Port로 접속 : 하드웨어가 알아볼 수 있도록 (30000~33000개 정도)<- 루트리스(wellKnown 포트 안 쓰려고 : 보안적)      
+ 루트로 돌면 쉘 명령어가 에러가 나와서 빠지면 쉘로 빠지게 됨: 프롬프트로 빠져나오면 바로 프롬프트 권한을 해킹 당할 수 있어서 RootLess로 돌림

### Road Balancer (중요)   
+ 외부 클러스터랑 통신 할 때만 'Road Balancer'라고 yaml라고 붙이게 됨
+ k8s에서는 proxy가 로드발란서 역할을 함 (클러스터 전체 파드의 아이피를 알고 있음)
+ 프록시는 전달, 실제는 IP Tables가 실행(리눅스 OS에 있음,L7의 기능까지 모두 있음), IP tables는 실물 닉한테 패킷 전달 함
+ => 실습과정에서 ip tables에서 1,1,1,1로 넣어준 것

### Sync <> Async   
동시 요청 많은 웹/api서버는 async가 기본이고, 단순한 서버나 CPU작업은 sync도 충분: 파이썬 웹서버는 거의 다 async로 쓰는 추세  >DB, 다른 API,파일/NFS 기다리는 동안 I/O 하는 일이 대부분인 웹서버는 async로 기다리는 동안 다른 요쳥 처리하고, 스레드 덜 쓰는 것이 리소스 효율에 좋다.
